# RB-002 High CPU saturation (version 1, current)

## Supported incident types
cpu; latency caused by saturation

## Preconditions
CPU is 80 percent or higher for 5 minutes. The service has fewer than 10 replicas.

## Investigation steps
1. Compare CPU with the request rate: a matching rise suggests real traffic growth.
2. Look for saturated thread pools or growing request queues in the logs.
3. Check for a retry storm: request volume rising after upstream failures.
4. Confirm the replica count and the maximum of 10.

## Approved remediation
Scale the service out (operation scale, parameter replicas, at most double the current count and never above 10).

## Required permission
Engineer approval

## Risks and side effects
Higher cost. More connections to the database and other dependencies.

## Rollback procedure
Scale back to the original replica count.

## Verification criteria
CPU below 80 percent and latency below 1 second for 5 minutes.

## Escalation
If CPU stays high with normal traffic, suspect a code regression and open RB-001.
