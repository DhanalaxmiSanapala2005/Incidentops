# RB-003 Memory exhaustion and suspected memory leak (version 1, current)

## Supported incident types
memory

## Preconditions
Memory is 85 percent or higher. No OOM crash loop yet (otherwise use RB-005).

## Investigation steps
1. Check whether memory grows steadily over time (leak) or jumps with a job or deployment.
2. Look for garbage collection warnings and out of memory errors.
3. Check for a deployment or configuration change near the start of the growth.

## Approved remediation
Rolling restart of the service to release memory (operation restart). Capture a heap dump first when possible and open a bug for the owner.

## Required permission
Engineer approval

## Risks and side effects
Short capacity loss. Caches start cold and latency may rise briefly.

## Rollback procedure
A restart cannot be undone; the service restarts on its own if it fails.

## Verification criteria
Memory below 85 percent after 10 minutes and health check healthy.

## Escalation
If memory climbs back above 85 percent within 30 minutes, the leak persists: use RB-009 and escalate.
