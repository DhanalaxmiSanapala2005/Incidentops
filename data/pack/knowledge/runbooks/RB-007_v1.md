# RB-007 Bad configuration change or feature flag (version 1, current)

## Supported incident types
latency; error_rate after a configuration change

## Preconditions
A configuration or feature flag change happened shortly before the symptoms. The key is on the allowlist.

## Investigation steps
1. Read the configuration change events and match their time with the start of the symptoms.
2. Check the logs for messages that mention the changed key, such as cache miss ratio.
3. Confirm the previous value from the change record.

## Approved remediation
Revert the key to its previous value (operation config_change; allowed keys are feature.new_pricing_engine, cache.ttl_seconds and db.pool.max_connections).

## Required permission
Engineer approval

## Risks and side effects
Reverting may undo an intended change. Cached data may be rebuilt.

## Rollback procedure
Set the key back to the value it had before the revert.

## Verification criteria
Latency and error rate back to baseline within 10 minutes.

## Escalation
If the revert does not help, the change was not the cause: continue with RB-004.
