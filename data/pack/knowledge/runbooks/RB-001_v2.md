# RB-001 Elevated error rate after a deployment (version 2, current)

## Supported incident types
error_rate; latency when it starts right after a deployment

## Preconditions
Error rate is 5 percent or higher on the affected service. A deployment to that service finished within the last 60 minutes. A previous version exists in the sandbox.

## Investigation steps
1. Compare the time the error rate began with the time of the latest deployment.
2. Search the logs for the most frequent exception and confirm it first appears after the deployment.
3. Check traces: the failing span should be inside the affected service, not in a dependency.
4. Read the previous version number from the deployment history.

## Approved remediation
Roll back the service to the previous version (operation rollback, parameters service and target_version).

## Required permission
Engineer approval

## Risks and side effects
Features in the new version disappear. In-flight requests may fail for a few seconds.

## Rollback procedure
Redeploy the newer version (operation rollback to the newer version number).

## Verification criteria
Error rate below 5 percent (target below 1 percent) and p95 latency below 1 second for 5 minutes, health check healthy.

## Escalation
If errors persist after rollback, escalate to the service owner and open RB-009.
