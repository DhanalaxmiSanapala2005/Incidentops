# RB-012 Database connection pool exhaustion (version 1, current)

## Supported incident types
latency; error_rate

## Preconditions
Logs show waiting for a connection from the pool and active connections equal the maximum.

## Investigation steps
1. Confirm active connections equal the pool maximum.
2. Check that slow queries are not the main cause.
3. Check database load before raising the pool size.

## Approved remediation
Raise db.pool.max_connections (operation config_change, allowed range 5 to 200, at most triple the current value).

## Required permission
Engineer approval

## Risks and side effects
More connections can overload the database.

## Rollback procedure
Set db.pool.max_connections back to the previous value.

## Verification criteria
No pool wait errors and p95 latency below 1 second for 5 minutes.

## Escalation
If database CPU rises above 90 percent, revert and escalate to the database team.
